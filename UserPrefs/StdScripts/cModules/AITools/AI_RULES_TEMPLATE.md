# 3DCoat-Live AI Agent Rules

> **Rules file integrity:** This rules file MUST NEVER be deleted, moved, renamed, overwritten, or modified by the agent.

1. **MCP Server**: Always use the `3dcoat-live` MCP server. If it doesn't respond or there was an error during its activation, try refreshing the `3dcoat-live` MCP server. If it still doesn't work, ask the user to ensure 3DCoat is running and that the DevTools extension is activated in the Extensions window.
2. **Dynamic Scripts**: If the user asks to do something directly in 3DCoat and there is no suitable MCP command, research how to write a script to achieve it. Execute it using the `run_script_from_source` MCP command WITHOUT saving the script itself to a file.
3. **Crash Handling**: If the `3dcoat-live` MCP server stops responding after running a script in 3DCoat, it is highly likely that the script execution caused a 3DCoat crash. Check the 3DCoat logs, fix the errors, and ask the user to restart 3DCoat. After the restart, refresh the `3dcoat-live` MCP server (it will have a new port).
4. **Creating GPU Nodes**: All nodes have a `.glsl` extension. The list of existing nodes and their initial code can be obtained using the `get_std_GPU_Nodes` command. If the user wants to create a new node for a shader, material, post-effect, adjust layer, or GPU node - create it in this project's folder within the `GPUNodes` subfolder (if the `GPUNodes` folder doesn't exist, create it). Then, inside a subfolder named after the category (check via `get_std_GPU_Nodes` if a suitable category subfolder already exists in this project's `GPUNodes`; if not, create one). Write the initial node code into a file there, where the filename must match the node name, and the extension must be `.glsl`. However, the filename MUST NOT contain spaces or other characters that are invalid in GLSL variable names. Nodes are written in a GLSL-like language that has some differences, so please adhere to the NodeGraph Language (NGL) Rules.
5. **Modifying GPU Nodes**: If the user wants to modify an existing node, find the path to its file using the `get_std_GPU_Nodes` command, retrieve its initial code using `get_std_GPU_Nodes`, and save it in this project's `GPUNodes` folder, preserving the rest of the path from the original file (including the filename).
6. **Creating Extensions (cExtensions)**: If the user wants to write an extension (cExtensions), they are written exactly the same way as modules. You can inspect how modules are written in the `cModules` folder and write new extensions following their structure. However, extensions are saved in this project's `cExtensions` subfolder, followed by a folder with the extension's name, containing a `.py` file that instantiates a class inheriting from `cExtension` (this is the file that will be imported when the extension is activated).

7. **Modeling and Primitives**: When the user asks you to model something, create geometry, or spawn a primitive, you MUST do this strictly by writing and executing a Python script using the 3DCoat Python API via the `run_script_from_source` tool. DO NOT attempt to create models or geometry by manipulating the UI (e.g., using UI introspection, clicking buttons, filling fields). UI manipulation is completely unsuitable and impossible for modeling tasks. If you need to understand the modeling API, use the `read_3dcoat_modeling_guide` tool first.
8. **UI Navigation and Tools**: If the user asks where a specific tool is located (e.g. "where is Geometry Info bake?"), **NEVER** guess or assume its location based on generic 3D software knowledge. You MUST use the `search_ui_commands` tool first to find the exact ID and location, or use `get_full_ui_description_as_json` to inspect the actual interface. Only give an answer AFTER you have verified it using the MCP tools.
9. **UI Values and Percentages**: When reading values from the UI, look for the `is_percentage` and `displayed_value` fields in the JSON. If `is_percentage` is `true`, you MUST say the value as a percentage using the `displayed_value` (e.g., say "50%", NOT "0.5"). However, when writing python code (`setSliderValue`), you must ALWAYS pass the raw fractional `current_value` (e.g., `0.5`), as the Python API expects the internal real value, not the display value.
10. **UI Interaction Rules**:
    1. **DO NOT GUESS WIDGET IDs**: When you need to point out a UI element using `point_out_ui_element`, you must FIRST use `get_full_ui_description_as_json` or `search_ui_commands` to find its exact `id`. Guessing an ID like `cmd("ToggleSymmetry")` without verifying will cause errors.
    2. **USE NATURAL NAMES**: When communicating with the user, DO NOT speak internal IDs or weird prefixes (e.g., "$IncRes", "#ToggleWireframe"). Instead, speak the natural human-readable name of the button (e.g., "Increase resolution", "Wireframe").
    3. **DO NOT SPEAK WHILE EXECUTING TOOLS**: You must call all necessary tools silently. Only speak AFTER you have finished all tool calls and are providing your final answer.
    4. **POINT OUT THE PANEL, NOT THE MENU**: If the user asks to show or explain a window/panel/tab, DO NOT point at the simple menu item that opens it! Use the `find_open_window_id` tool to search for the open Window/Panel container ID. If the tool says it is not open, use `run_script_from_source(coat.ui.cmd(...))` to open the tool first, run `find_open_window_id` again, and then point it out.
    5. **POINT OUT UI DURATION**: When using `point_out_ui_element`, ALWAYS set `dim_duration=8000` and `highlight_duration=16000`.
    6. **MODAL DIALOGS**: Before trying to execute actions in the UI, call `get_active_modal_json()`. If `"status": "modal_open"`, it means 3DCoat is blocked by a modal dialog. You cannot interact with the main interface until it is closed. Read `"dialog_meta"` to understand what it wants. If it's a simple Warning/Error, use `run_script_from_source` to click 'Yes' or 'OK' via `coat.ui.cmd()`. If it's a complex export or settings dialog, explain `"main_message"` to the user and ask what parameters they want to set before clicking "OK".
